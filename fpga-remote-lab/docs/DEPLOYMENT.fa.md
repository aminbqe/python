# انتشار و عیب‌یابی

## نشانی‌های فعلی

پنل فیزیکی در `https://aminbagheri.com/rasp/` و مبدل مستقل در `https://aminbagheri.com/fpga/` قرار دارد. مبدل روی هاست معمولی قابل ارائه است، ولی عامل JTAG/UART باید روی دستگاه متصل به برد اجرا شود.

## مسیر اینترنتی

```text
مرورگر → HTTPS /rasp/ → Cloudflare Worker
       → hostname مبدأ تونل → cloudflared روی رزبری
       → http://127.0.0.1:8000/rasp/
```

Worker در `deploy/cloudflare/rasp-worker.mjs` آپلود و WebSocket را عبور می‌دهد، Origin مرورگر را قبل از بازنویسی کنترل می‌کند و مسیر عامل را در سمت عمومی می‌بندد. متغیر `RASP_ORIGIN` باید hostname تونل خودتان باشد. `wrangler.jsonc` نمونهٔ مسیر فعلی است؛ برای دامنهٔ دیگر آن را اصلاح کنید.

برای تونل نام‌دار، hostname عمومی مبدأ را به سرویس `http://127.0.0.1:8000` و مسیر `^/rasp(/.*)?$` متصل کنید. DNS و مسیر Worker باید به همان zone مربوط باشند. درخواست‌های وب و WebSocket را هر دو بررسی کنید؛ باز شدن داشبورد Cloudflare در مرورگر، سلامت اتصال cloudflared به edge را ثابت نمی‌کند.

## ابزار Python انتشار

`deploy/cloudflare/deploy_rasp.py` ابزار نگهداری است و برای اجرای سرور لازم نیست. نسخهٔ منتشرشده شناسهٔ حساب، تونل و دامنه را از محیط می‌خواند. فایل توکن خصوصی را خودتان در `.deploy-wheels/cloudflare-api-token.txt` بسازید و دسترسی آن را محدود کنید. این فایل و پشتیبان‌ها نباید به Git اضافه شوند.

```sh
export CF_ACCOUNT_ID='your-account-id'
export CF_TUNNEL_ID='your-tunnel-id'
export CF_DOMAIN='your-domain.example'
python deploy/cloudflare/deploy_rasp.py
```

اجرای پیش‌فرض فقط وضعیت را می‌خواند، پشتیبان و برنامهٔ تغییر می‌سازد. این اسکریپت برای تونل و Worker ازقبل‌ساخته‌شده طراحی شده است. `--apply` تغییرات واقعی DNS، ingress، Worker و route را انجام می‌دهد. قبل از آن برنامه و پشتیبان را بررسی کنید؛ منطق اسکریپت برای حفظ ایمیل و رکوردهای دامنهٔ اصلی طراحی شده و برای هر zone قابل فرض نیست. در دامنهٔ متفاوت، قواعد DNS داخل کد را بازبینی کنید. توکن API برای انتشار با توکن اجرای cloudflared متفاوت است.

## مبدل روی cPanel

پوشهٔ `deploy/cpanel/fpga` نسخهٔ مستقل HTML/JS/PHP مبدل است. محتویات آن را در پوشهٔ عمومی `/fpga/` هاست قرار دهید. PHP برای نگهداری موقت و دانلود ZIP است و نیاز به دسترسی نوشتن در محل موقت تنظیم‌شده دارد. تولید پروژه در مرورگر انجام می‌شود؛ ISE روی هاست اجرا نمی‌شود.

`deploy/build_cpanel.py` سازندهٔ اولیهٔ بسته است؛ نسخهٔ نهایی `core.js`، PHP و اصلاحات دانلود در پوشهٔ آمادهٔ cPanel نگهداری می‌شوند. اجرای سازنده ممکن است تغییرات نسخهٔ نهایی را بازنویسی کند؛ خروجی آن را قبل از جایگزینی بازبینی کنید. برای انتشار فعلی از پوشهٔ آماده استفاده کنید.

## عیب‌یابی کوتاه

| نشانه | بررسی |
| --- | --- |
| آپلود 401 | رمز صحیح مدیر و تنظیم هش؛ رمز پس از 401 در فرم پاک می‌شود |
| آپلود 503 | تنظیم هش یا اتصال عامل؛ متن پاسخ را ببینید |
| آپلود 409 | جلسهٔ قبلی هنوز وجود دارد |
| JTAG متصل ولی UART قطع | قالب بیت‌فایل، پایه‌ها، سطح منطقی، کنسول سریال و baud |
| FPGA پیدا نمی‌شود | برق برد، کابل، شناسهٔ FTDI، دسترسی USB و خروجی `openFPGALoader` |
| پنل باز می‌شود ولی زنده نیست | WebSocket، Origin، route و اتصال عامل محلی |
| ZIP در Chrome خطا می‌دهد | وجود فایل و مهلت نگهداری، endpoint PHP، HTTP headers و تداخل افزونهٔ دانلود |
| تونل timeout می‌شود | لاگ cloudflared، دسترسی edge و مسیر شبکه؛ TCP/UDP و HTTP/2 را مطابق محیط بررسی کنید |
| systemd نام سرویس را با `\x0d` نشان می‌دهد | فایل اسکریپت CRLF است؛ پایان‌خط‌ها را به LF تبدیل کنید |

در برخی شبکه‌ها مسیر پراکسی اختصاصی استفاده شده است. `tunnel_dns.py` صرفاً DNS روی loopback با DoH از پراکسی محلی پورت 10809 است؛ خودش VPN یا TUN ایجاد نمی‌کند. این مخزن کانفیگ VPN، رمز، توکن تونل یا تنظیمات مسیریابی خصوصی ندارد.

## نگهداری

قبل از تغییر DNS یا سرویس‌ها پشتیبان بگیرید. `.env` را با مجوز 0600 نگه دارید. برای به‌روزرسانی فایل‌های برنامه از رمزها و تنظیمات فعلی محافظت کنید. برای قطع دسترسی عمومی، route Worker را بردارید؛ برای توقف برنامه، سرویس‌های کاربر `fpga-lab` و `fpga-agent` را متوقف کنید. توقف عامل ممکن است طرح را در ریست نگه دارد.
