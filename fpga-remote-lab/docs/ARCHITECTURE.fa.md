# معماری و قرارداد ارتباطی

`server.py` یک برنامهٔ FastAPI با وضعیت مشترک در حافظه است. مرورگر از WebSocket وضعیت و رویدادها را می‌گیرد. عامل `pi_agent.py` با توکن مستقل به `/agent` وصل می‌شود، فایل را از سرور می‌گیرد، تراشهٔ هدف را بررسی و با `openFPGALoader` در SRAM پروگرام می‌کند. UART به‌صورت دوره‌ای ورودی‌ها و پاسخ طرح را منتقل می‌کند.

## مسیرهای اصلی

| مسیر | کاربرد |
| --- | --- |
| `GET /` یا `/rasp/` | پنل وب |
| `POST /api/upload` یا `/rasp/api/upload` | multipart با فیلد `file` و هدر `X-Upload-Password` |
| `/ws` یا `/rasp/ws` | WebSocket مرورگر |
| `/agent` | WebSocket عامل با `Authorization: Bearer <AGENT_TOKEN>` |
| `/api/verilog/inspect` | بررسی پورت‌های سورس |
| `/api/verilog/files` | کد فایل‌های تولیدی |
| `/api/verilog/prepare-download` | آماده‌سازی ZIP |

عامل باید به ریشهٔ محلی مانند `http://127.0.0.1:8000` متصل شود؛ مسیر عمومی Worker دسترسی به عامل را مسدود می‌کند. برای فهرست دقیق API و مدل‌های داده، پس از اجرای محلی `/docs` را ببینید.

## قرارداد UART

115200 baud، 8N1. همهٔ اعداد چندبایتی little-endian هستند.

درخواست میزبان ۱۲ بایت:

```text
A5 | buttons[3:0]:switches[3:0] | reset(bit0)
   | input_a(4 bytes) | input_b(4 bytes) | XOR(previous 11 bytes)
```

پاسخ FPGA هفت بایت:

```text
5A | leds[3:0] | result(4 bytes) | XOR(previous 6 bytes)
```

عامل تقریباً هر ۱۵۰ میلی‌ثانیه درخواست می‌فرستد و پاسخ‌ها را به LED و نتیجهٔ عددی پنل تبدیل می‌کند. بستهٔ ناقص یا checksum اشتباه پذیرفته نمی‌شود. بدون پاسخ معتبر بیش از حدود ۱٫۵ ثانیه وضعیت UART نامعتبر می‌شود. پس از نخستین درخواست معتبر، watchdog قالب با قطع درخواست‌ها برای یک ثانیه ریست را فعال می‌کند. طرح کاربر باید ریست را رعایت کند.

چهار بیت LED به پایه‌های P4، N5، P5 و M6 وصل‌اند. سون‌سگمنت در بستهٔ فعلی جای ندارد. افزودنش نیازمند تغییر هم‌زمان قالب، پروتکل و عامل است. رابط از نظر ساختاری `digits` دارد، اما عامل فعلی آن را نمونه‌برداری نمی‌کند.

## محدودهٔ فعلی

- یک عامل و یک جلسهٔ مشترک؛ صف کاربران، مالکیت جلسه و حساب کاربری وجود ندارد.
- بررسی حضور USB، پاسخ JTAG و تازگی UART جداگانه انجام می‌شود؛ هیچ‌کدام به‌تنهایی تمام مسیر را اثبات نمی‌کند.
- پروتکل دارای `input_a` و `input_b` است؛ پنل فعلی کنترل عمومی برای ورود این دو عدد ندارد. کلیدها و دکمه‌ها مسیر اصلی ورودی مثال‌های سایت‌اند.
- کنترل‌های مجازی جای فشردن فیزیکی کلید برد نیستند؛ مقادیر به منطق کاربر در قالب داده می‌شوند.
- رمز آپلود فقط endpoint آپلود را محافظت می‌کند. درخواست با رمز اشتباه 401 و نبود هش تنظیم‌شده 503 برمی‌گرداند. سایر کنترل‌ها احراز هویت کاربر ندارند.
- تطبیق تراشهٔ `6slx9ftg256` امنیت نگاشت پایه‌های هر بیت‌فایل دلخواه را تضمین نمی‌کند؛ این نسخه برای آزمایشگاه مورداعتماد است.
- برنامه چند worker یا چند replica با وضعیت مشترک پایدار ندارد؛ Uvicorn را برای این نسخه با یک worker اجرا کنید.
